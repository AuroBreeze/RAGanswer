# 工厂知识问答机器人前后端接口协议

| 项目 | 约定 |
| --- | --- |
| 文档版本 | 1.0 草案，供前后端评审和联调 |
| 接口前缀 | `/api/v1` |
| 首版交付 | 带出处问答、多轮追问、资料不足提示、出处预览 |
| 扩展接口 | SSE 流式输出、文档入库、历史记录、高频问题、岗前自测 |

## 1. 对接方式

前端负责输入、加载、聊天记录展示、引用定位与错误提示。后端负责会话、权限、文档解析和检索、答案生成、引用校验与响应状态。前端使用本文件的请求与响应契约接入，后端可独立调整模型、检索策略和向量库。

| 项目 | 约定 |
| --- | --- |
| 地址 | 前端通过环境变量配置 `API_BASE_URL`，只放域名和端口。请求路径自带 `/api/v1` |
| 本地联调 | 可由前端开发服务器代理 `/api`；采用跨域直连时，由后端按环境配置允许的前端来源 |
| 请求与响应 | JSON 使用 UTF-8、字段用 `snake_case`。文件上传、文件预览和 SSE 使用各节声明的媒体类型 |
| 认证 | 联调和部署使用 `Authorization: Bearer <access_token>`，令牌由项目登录模块发放。Mock 可直接返回样例 |
| 时间 | 请求与响应使用带时区的 ISO 8601 值，例如 `2026-11-21T08:30:00+08:00` |
| 标识符 | 除单条消息内的引用编号外，所有 ID 都以不透明字符串传输，客户端按原值保存 |
| 请求追踪 | 每次请求生成 `request_id`，响应头为 `X-Request-ID`。有 JSON 问答成功体或公共错误体时，正文携带相同值 |

跨域直连时，允许 `Authorization`、`Content-Type` 和 `Idempotency-Key` 请求头，并暴露 `X-Request-ID`、`Retry-After` 响应头。文档预览和会话资源均按登录身份校验访问权限。设备型号、车间编号和受众参数只提供查询上下文。

## 2. 首版接口

| 方法和路径 | 用途 |
| --- | --- |
| `POST /api/v1/chat` | 创建一轮问答，首轮自动创建会话 |
| `GET /api/v1/documents/{document_id}/content` | 获取引用对应版本的文档原件或预览文件 |

### 2.1 提问 `POST /api/v1/chat`

请求体使用 `application/json`。请求示例中的身份、设备和文件均为联调假数据。

```json
{
  "question": "新员工在哪里领取培训签到表？",
  "conversation_id": null,
  "audience": "new_employee"
}
```

| 字段 | 类型 | 必填 | 规则 |
| --- | --- | --- | --- |
| `question` | string | 是 | 去掉首尾空白后为 1–2000 个 Unicode 字符 |
| `conversation_id` | string 或 null | 否 | 省略或传 null 时创建会话。后续传服务端返回的 ID。空字符串为无效参数 |
| `audience` | enum | 否 | `new_employee` 用于新员工，`manager` 用于管理者。默认 `new_employee`，对当前回答生效 |
| `context` | object | 否 | 可传 `site_id`、`workshop_id`、`equipment_model`，均为字符串。省略表示未指定。前端有车间或设备选择器时再传 |

客户端若希望超时后安全重试，应为每次用户主动发送生成一个 UUID，放在 `Idempotency-Key` 请求头。客户端应为新问题生成新键，重试同一次发送应沿用原键和原请求体，包括首轮的 `conversation_id: null`。重放规则见第 5 节。

#### 成功响应

三个业务状态均返回 HTTP `200`。所有顶层字段均存在。

```json
{
  "request_id": "req_8ab2",
  "conversation_id": "conv_123",
  "message_id": "msg_456",
  "status": "answered",
  "message": "请到培训室前台领取签到表。[1]",
  "citations": [
    {
      "id": 1,
      "document_id": "doc_onboarding_v3",
      "title": "新员工培训须知",
      "version": "V3",
      "section": "2.1 培训签到",
      "page": 4,
      "excerpt": "新员工培训签到表由培训室前台发放。",
      "url": "/api/v1/documents/doc_onboarding_v3/content"
    }
  ]
}
```

| 字段 | 类型 | 规则 |
| --- | --- | --- |
| `request_id` | string | 对应这次 HTTP 请求，用于日志定位 |
| `conversation_id` | string | 后续轮次沿用 |
| `message_id` | string | 助手消息 ID，用于历史记录、去重或后续反馈 |
| `status` | enum | 取值见下表 |
| `message` | string | 纯文本，支持换行。前端以文本渲染，按下文规则绑定引用 |
| `citations` | array | 元素结构见 2.2 节。无引用时为 `[]` |

| 状态 | 服务端规则 | 界面行为 |
| --- | --- | --- |
| `answered` | 依据可核验且适用的资料回答。引用数组至少一条 | 展示回答及可点击的引用编号、来源卡片 |
| `needs_clarification` | 型号、车间、设备标识等信息影响检索或资料适用性。返回一个具体问题及空引用数组 | 展示追问。用户补充信息时沿用当前会话 |
| `insufficient_evidence` | 资料缺失、适用版本无法确认或现有资料冲突且无法解决。说明无法确认的内容，引用数组为空 | 展示提示，允许补充信息或重新提问 |

**待澄清示例**

```json
{
  "request_id": "req_8ab3",
  "conversation_id": "conv_124",
  "message_id": "msg_457",
  "status": "needs_clarification",
  "message": "请提供设备型号或设备编号，我可以据此查找对应的点检表。",
  "citations": []
}
```

用户回复「A-03」时，请求体为 `{"question":"A-03","conversation_id":"conv_124","audience":"new_employee"}`。后端结合会话中的原问题检索。前端在上一轮完成前禁用当前会话的发送按钮；后端也对同会话的并发请求做冲突检测。用户点「新对话」时，前端清空会话 ID。

**资料不足示例**

```json
{
  "request_id": "req_8ab4",
  "conversation_id": "conv_124",
  "message_id": "msg_458",
  "status": "insufficient_evidence",
  "message": "当前资料不足以确认 A-03 对应的点检表。请补充所在车间，或向设备管理员核实。",
  "citations": []
}
```

### 2.2 引用对象

| 字段 | 类型 | 规则 |
| --- | --- | --- |
| `id` | integer | 从 1 开始，在单条消息中连续且唯一。正文中的 `[1]` 对应 `id: 1` |
| `document_id` | string | 指向一份不可变的文档修订版。更新原文时分配新 ID |
| `title` | string | 用户能识别的文档标题 |
| `version` | string 或 null | 原文上的版本标签，例如 `V3`。未知时为 null |
| `section` | string 或 null | 条款编号、章节或小节标题 |
| `page` | integer 或 null | 从 1 开始的预览 PDF 文件页序，以查看器页序为准。无法准确定位时为 null |
| `excerpt` | string | 能支持该句的原文片段 |
| `url` | string 或 null | 后端提供的同 API 来源相对路径。没有可访问的预览时为 null |

后端从实际检索记录提取文档元数据和原文，校验正文编号与引用数组双向对应，并核对关键结论是否有出处。入库时保存适用设备、车间、版本和生效状态，检索时结合上下文及权限筛选。故障处置、维保和安全类问题若缺少适用依据，按 `needs_clarification` 或 `insufficient_evidence` 返回。

前端对 `[n]` 以单条消息的引用数组为准。卡片展示标题、版本、章节、页码和原文；可空字段缺失时隐藏。若收到未知引用编号，按普通文本展示并记录对应的 `request_id`。

### 2.3 打开引用原文

`GET /api/v1/documents/{document_id}/content` 在授权成功后返回可预览文件，例如 `Content-Type: application/pdf`。文档无预览资源或当前用户无法发现该资源时返回 `404`。前端遇到 `url: null` 时保留引用卡片和摘录，隐藏打开原文按钮。

Bearer 认证下，前端通过带认证头的 `fetch` 获取文件，再把 Blob 交给 PDF 查看器。定位使用引用对象里的 `page`，由查看器跳转。文件接口可返回 `200` 完整文件，首版无需实现 Range 请求。

## 3. SSE 流式问答（可选扩展）

`POST /api/v1/chat/stream` 接收与普通问答相同的 JSON 请求体。前端通过 `fetch` 发起 POST，并读取响应流。请求声明 `Accept: text/event-stream`，成功响应为 `200` 和 `Content-Type: text/event-stream; charset=utf-8`。

| 事件 | `data` 格式 | 客户端行为 |
| --- | --- | --- |
| `meta` | `{"request_id":"req_8ab2"}` | 首个事件，记录请求 ID |
| `delta` | `{"text":"请到培训室前台"}` | 追加到当前临时气泡。可为零次或多次 |
| `result` | 与普通问答完全相同的成功响应体 | 用 `message` 替换临时内容，渲染状态和引用，并保存会话与消息 ID |
| `error` | 与第 5 节相同的公共错误体 | 移除临时内容，保留用户输入并展示错误 |

下例先发送一段澄清提示，再发送完整结果。涉及设备操作、故障处置、维保或安全的内容，后端确认结论和引用后再发送正文。也可省略 `delta`，直接发送 `result`。

```text
event: meta
data: {"request_id":"req_8ab3"}

event: delta
data: {"text":"请提供设备型号"}

event: result
data: {"request_id":"req_8ab3","conversation_id":"conv_124","message_id":"msg_457","status":"needs_clarification","message":"请提供设备型号或设备编号，我可以据此查找对应的点检表。","citations":[]}

```

- 每个事件以空行结束。前端按事件边界解析，保留跨网络分片的未完成文本。空闲时后端可发 `: ping` 注释作为心跳。
- 参数和权限错误在开始推流前通过 HTTP 错误响应返回。开始推流后的业务处理失败通过 `error` 事件返回。
- 服务端在 `result` 或 `error` 后结束流。连接在终止事件前关闭时，前端按中断处理。重试沿用原幂等键和原接口。若上一轮已完成，服务端可只回放 `meta` 和 `result`。
- 代理有缓冲时按部署配置关闭该路由的响应缓冲。前端点击停止时可结束本地读取，服务端是否已完成由幂等重试结果确认。

## 4. 文档、历史与业务扩展

本节为新增能力的接口预案，默认在双方约定排期后启用。首版可以从服务端导入赛题文档。

### 4.1 管理员上传与入库

| 接口 | 请求 | 响应 |
| --- | --- | --- |
| `POST /api/v1/admin/documents` | `multipart/form-data`，含必填 `file`、`title`，可选 `version`、`site_id`、`equipment_model` | `202`，返回 `document_id`、`job_id`、`status: queued` |
| `GET /api/v1/admin/ingestion-jobs/{job_id}` | 路径传任务 ID | `200`，返回 `job_id`、`document_id`、`status`、`updated_at`、`error` |

状态顺序为 `queued → processing → ready`，任一处理中阶段失败可进入 `failed`。只有文档和索引均可查询时才标记 `ready`。`error` 在失败时返回 `{"code":"PARSE_FAILED","message":"文档解析失败。"}`，其他状态传 null。管理页可每 2 秒轮询一次，收到终态后停止；收到 `429` 时按 `Retry-After` 指示延后。上线该接口前再固定允许的文件类型、大小上限和批量导入方式。

### 4.2 会话与业务能力

| 场景 | 建议接口 | 对接数据 |
| --- | --- | --- |
| 历史消息 | `GET /api/v1/conversations/{conversation_id}/messages?limit=20&cursor=...` | 返回 `items`、`next_cursor`。消息含 `message_id`、`role`、`message`、`created_at`。助手消息额外保留 `status` 和 `citations` |
| 回答反馈 | `PUT /api/v1/messages/{message_id}/feedback` | 请求含 `rating: helpful\|unhelpful` 和可选 `comment`。同一用户重复提交覆盖已有反馈，成功返回 `204` |
| 高频问题 | `GET /api/v1/admin/analytics/top-questions?from=...&to=...&limit=10` | 按 `[from, to)` 统计，返回 `items`，每项含归并后的 `question` 和 `count`。是否按车间过滤由管理端页面需求决定 |
| 岗前自测 | `POST /api/v1/quizzes` | 请求含 `topic`、`audience`、`question_count`。返回 `quiz_id` 和题目列表，每题含 `question_id`、题干、选项及其 ID |
| 自测交卷 | `POST /api/v1/quizzes/{quiz_id}/submissions` | 请求传 `answers`，每项含 `question_id`、`selected_option_id`。返回总分、单题结果、解析和出处 |

分页接口统一使用不透明游标。会话消息按时间倒序分页，时间相同用消息 ID 保持稳定排序；`next_cursor: null` 表示到末页。高频统计按实际成功写入的用户消息计数，幂等重放沿用原记录。自测题的正确选项和解析在交卷后再返回。

## 5. 错误、超时和重试

JSON 错误体统一包含 `code`、`message`、`request_id`。参数校验可附 `details`，每项含 `field` 和 `reason`。前端按 `code` 分支，`message` 可直接展示。

```json
{
  "code": "INVALID_REQUEST",
  "message": "请填写问题。",
  "request_id": "req_8ab5",
  "details": [
    {"field": "question", "reason": "trimmed_empty"}
  ]
}
```

| HTTP | `code` | 触发条件及前端处理 |
| --- | --- | --- |
| 400 | `INVALID_REQUEST` | 字段校验失败，提示修改输入 |
| 401 | `UNAUTHENTICATED` | 缺少凭证、凭证无效或过期，进入重新登录流程 |
| 403 | `FORBIDDEN` | 当前身份不能调用该功能，例如普通用户访问管理接口 |
| 404 | `NOT_FOUND` | 会话或文档不存在，或当前身份无法发现该资源。会话失效时提示用户另开对话 |
| 409 | `CONVERSATION_BUSY` | 同一会话已有一轮处理中。等待后重试 |
| 409 | `REQUEST_IN_PROGRESS` | 同一个幂等键对应的请求仍在处理。等待后用原键重试 |
| 409 | `IDEMPOTENCY_CONFLICT` | 同一用户、同一路由使用同一个键提交了不同请求体 |
| 413 | `REQUEST_TOO_LARGE` | JSON 请求体超过限额，提示用户缩短输入 |
| 413 | `FILE_TOO_LARGE` | 上传文件超过限额，提示用户更换文件 |
| 415 | `UNSUPPORTED_MEDIA_TYPE` | 请求媒体类型或上传文件格式不受支持 |
| 429 | `RATE_LIMITED` | 请求过于频繁，按 `Retry-After` 等待 |
| 500 | `INTERNAL_ERROR` | 后端异常，保留输入与请求 ID |
| 503 | `SERVICE_UNAVAILABLE` | 检索或生成依赖超时、暂时不可用。允许用户重试 |

- 问答处理时限初定为后端 45 秒、代理至少 55 秒、前端 60 秒。联调时可按实际耗时一起调整。服务端能正常响应的超时统一返回 `503`；遇到网络断开或代理返回非 JSON 错误，前端显示通用失败提示。
- 幂等键按登录用户、HTTP 路径和键值隔离，有效期初定为 24 小时。后端在处理前登记请求，比较解析后的 JSON 值，并在成功记录消息时保存可重放结果。重放保留原 `conversation_id`、`message_id`，以这次请求的追踪 ID 更新 `request_id`。重放和读取历史消息时重新校验会话及来源的访问权限。引用来源权限已撤销时，历史接口可保留消息位置和时间，将助手正文替换为权限提示并清空引用；幂等重放返回 `403`。
- 同键的请求尚在执行时返回 `REQUEST_IN_PROGRESS`。临时失败且确认未写入问答记录时，允许同键重新执行。若结果已经写入，重试返回既有结果。后端对成功写入与幂等结果保存使用同一事务或等价的原子操作。
- 前端收到网络中断、`429`、`503` 或处理中状态时，可让用户重试，同时保留原输入和请求上下文。未发送幂等键时，超时后重新提交可能生成另一条消息。

## 6. 兼容与变更

- 双方用同一份版本化协议和 Mock 数据。新增可选字段或新路由可沿用 `v1`；字段删除、类型变更、默认语义改变或必须由页面识别的业务状态变更，应先协商迁移，再发布新版本。
- 客户端应容忍响应中的新增字段。若遇到未知 `status`，展示后端提供的纯文本 `message` 并记录 `request_id`。遇到未知错误码，按 HTTP 状态和通用错误界面处理。
- 可空字段用 `null` 表示未知或不可用，空集合用 `[]`。客户端可以保留引用对象供后续使用，页面逻辑基于明确的状态与结构化字段。
- 实现时建议从本协议同步出 OpenAPI 定义及三种业务状态和公共错误的 JSON 样例，前端 Mock 与后端验收共用这些数据。

## 7. 联调交付与验收

| 负责人 | 首次联调前交付 |
| --- | --- |
| 后端 | 联调 API 地址、测试账号或令牌获取方式、四类 Mock、带页码的演示文档、可复现的提问样例 |
| 前端 | 可切换 Mock/联调环境的问答页、三种业务状态、引用卡片和原文预览、错误与重试交互 |
| 双方 | 约定首版路由、认证方式、预览格式、超时配置、测试样例和已启用的扩展 |

| 用例 | 预期结果 |
| --- | --- |
| 首轮有答案 | 创建会话，正文出现引用编号，点击能定位到同一版文档的正确页并核对原句 |
| 信息不全 | 先问「点检表在哪」，补充设备型号后复用同一会话并得到对应结果 |
| 资料不足 | HTTP `200`，展示无法确认的说明，引用数组为空 |
| 服务异常 | 返回统一错误体，界面保留输入，请求 ID 可用于查日志 |
| 首轮超时重试 | 原键和原请求体重试，同一次提交只产生一份会话和问答记录 |
| 文档权限 | 用无权账号请求已有引用的文件地址，服务端拒绝访问 |
| 版本追溯 | 更新文档后，新问答引用新版本，旧消息仍可指向历史版本中用户有权访问的原文 |
| 流式中断（启用 SSE 时） | 临时文本有明确的未完成状态，重试后由 `result` 完整替换并显示出处 |

## 8. 请求体安全与权限控制

### 8.1 传输和字段校验

- 联调和部署环境通过 HTTPS 传输请求。访问令牌通过 `Authorization` 请求头发送。前端可以提前提示输入错误，后端仍对每个请求独立校验。
- `/chat` 和 `/chat/stream` 共用请求校验。JSON 请求体大小初定为 32 KiB，在读取时限制实际字节数。后端按第 2.1 节校验问题长度、受众枚举、字段类型等规则，并对当前版本未声明的字段返回 `400 INVALID_REQUEST`。后续新增可选请求字段时，先部署支持该字段的后端，再更新前端。
- `question` 允许正常的中文、编号及标点。将用户问题和检索原文作为数据传入模型。服务端代码控制可访问的会话、文档和工具范围。前端将 `message`、`excerpt` 作为文本渲染。
- 应用日志默认记录 `request_id`、路由、状态和耗时。令牌、完整问题、原文摘录及模型输入默认排除在日志外。业务会话记录按约定的保留期管理，并受会话访问控制约束。若调用外部模型，只发送回答所需的获准内容，部署前确认内部资料可按项目约定发送给该服务。

### 8.2 服务端权限决策

服务端验证登录令牌，并根据账号确定角色和可访问的厂区、车间及文档范围。权限范围由服务端数据推导。`audience` 只控制回答风格，`context` 只缩小查找范围。

| 前端传入或请求的对象 | 后端校验 |
| --- | --- |
| `audience: "manager"` | 可按管理者风格组织用户有权获取的内容。管理接口始终要求账号具有管理权限 |
| `context.site_id`、`context.workshop_id` | 验证查询范围属于当前账号的授权范围。无权访问时返回通用 `404 NOT_FOUND` |
| `conversation_id` | 每轮问答及历史查询都验证当前账号有权访问该会话。无权访问时返回通用 `404 NOT_FOUND` |
| 文档原文路径中的 `document_id` | 点击引用时重新校验当前账号对该文档版本的访问权限。无权访问时返回通用 `404 NOT_FOUND` |
| 管理和统计接口 | 每次调用校验所需的管理角色及授权范围。缺少功能权限返回 `403 FORBIDDEN` |

### 8.3 RAG 权限执行顺序

**校验身份与会话 → 构造授权筛选条件 → 检索有权访问的文档 → 校验历史上下文和候选片段 → 生成答案 → 校验引用与响应。**

- 权限筛选应带入关键词检索与向量检索。若检索组件只能返回未过滤候选，服务端先做权限过滤，再把片段交给重排模型或生成模型。引用标题、摘录、页码和地址也只来自授权文档。
- 如果权限发生变化，构建下一轮模型上下文时，重新检查历史消息中引用的文档权限。移除包含已撤销资料的历史助手消息或摘要，再生成下一轮。展示历史和幂等重放遵循第 5 节的权限规则。
- 若引入检索或答案缓存，按有效权限范围及其版本区分缓存，并在读取时执行当前权限校验。会话历史进入模型的内容也要与当前授权范围一致。

### 8.4 安全联调用例

| 操作 | 预期结果 |
| --- | --- |
| 普通员工将 `audience` 改成 `manager` | 只影响表达方式，答案与引用仍来自该账号有权查看的资料 |
| 请求体自带 `role`、`user_id` 或其他未声明字段 | 返回 `400 INVALID_REQUEST` |
| 账号 A 提交账号 B 的会话 ID，或直接访问无权查看的文档版本 | 返回 `404 NOT_FOUND`，响应不暴露资源详情 |
| 问题命中一段受限原文，但当前账号无查看权限 | 该片段不进入重排或生成模型，也不出现在答案、引用或原文预览中 |
| 浏览历史后撤销账号的文档权限，再追问或用原幂等键重试 | 已撤销的资料不进入下一轮模型输入，重放按权限规则返回错误 |
